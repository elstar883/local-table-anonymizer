# Local Table Anonymizer

## Когда использовать

Используй этот Skill, когда нужно построить, изменить или проверить локальный
анонимизатор табличных данных: CSV/XLSX, персональные данные, обратимые
псевдонимы, зашифрованный словарь, деанонимизация и отчёт о восстановлении.

## Границы

- Skill не расширяет разрешения агентов. Каждый агент действует только в рамках
  своих прав.
- `references/requirements.md` доступен только для чтения.
- Нельзя добавлять реальные имена, телефоны, адреса, паспорта и другие ПДн.
- Нельзя добавлять сетевые запросы, внешние API, CDN, шрифты, картинки,
  аналитику и облако.
- Нельзя добавлять ML-библиотеки, LLM, эмбеддинги и обучение.
- Нельзя логировать ПДн и пароли.
- Нельзя делать API публичным или отключать проверку токена.
- Skill сам не изменяет файлы. Это делает Build после разрешения человека.

## Обязательные инварианты

1. **Офлайн.** Только `127.0.0.1`; ни одного сетевого вызова.
2. **Без ML.** Только regex, нормализация, HMAC, scrypt, HKDF, AES-GCM.
3. **Обратимость.** `INDEX` восстанавливается байт-в-байт; `HASH`/`MASK` —
   нет.
4. **Псевдонимность.** Псевдоним не раскрывает исходное значение.
5. **Приватность словаря.** Оригиналы только в AES-256-GCM.
6. **Детерминированность.** Одинаковое значение + ключ → одинаковый псевдоним.

## Workflow

1. **Чтение исходников.** Прочитай `AGENTS.md`, `references/requirements.md`,
   `references/acceptance-report.md`, `docs/ARCHITECTURE.md`, `SECURITY.md` и
   код `lta/`.
2. **`/lta-plan`.** Спроектируй этап: слои, данные, криптографию, тесты, UI,
   риски. Не меняй файлы.
3. **Подтверждение.** Покажи человеку спорные решения, объём этапа и риски.
   Дождись явного разрешения.
4. **`/lta-build`.** Реализуй только согласованный этап, сохраняя инварианты и
   работающие части.
5. **Проверка.** Запусти `python3 scripts/validate.py`,
   `python3 tests/test_lta.py`, `bash scripts/e2e.sh`. Для UI проверь 1440, 768,
   390 и 360 px.
6. **`/lta-qa`.** Передай реализацию на независимый аудит. QA возвращает
   таблицу доказательств и один статус, но ничего не исправляет.
7. **Согласованные исправления.** После разрешения человека исправь только
   подтверждённые пункты и повтори проверку.

## Критерии результата

- `test_roundtrip`: `INDEX`-значения восстанавливаются байт-в-байт.
- `test_determinism`: одинаковые значения дают одинаковые псевдонимы; разные
  проекты — разные.
- `test_wrong_password`: неверный пароль отклоняется.
- `test_hash_mask`: `HASH` детерминирован, `MASK` скрывает части значения.
- `test_offline`: сетевые вызовы заблокированы.
- `test_tableio_roundtrip`: CSV читается и пишется без потерь.
- E2E: 5000 строк, 7 `INDEX`-столбцов, 0 расхождений, 0 not found.
- `validate.py`: нет секретов, внешних URL, ML и сетевых импортов.
- UI: нет горизонтального переполнения на 1440, 768, 390 и 360 px.
- README, CHANGELOG и acceptance report соответствуют коду.
- Ограничения MVP описаны честно.

## Карта кода

- `lta/app.py` — Flask UI и API; не содержит криптографии.
- `lta/core.py` — анонимизация и деанонимизация.
- `lta/transform.py` — типы, нормализация, HASH, MASK.
- `lta/project.py` — проект и словарь.
- `lta/crypto.py` — scrypt, HKDF, AES-GCM, HMAC.
- `lta/tableio.py` — CSV/XLSX.
- `tests/test_lta.py` — юнит-тесты.
- `tests/api_test.py` — E2E.
- `scripts/validate.py` — структура и ограничения.
- `scripts/e2e.sh` — сервер + E2E.

## Частые ошибки

- Добавить `requests` или `urllib` в runtime.
- Забыть, что `uploads/` хранит файлы в открытом виде.
- Считать `HASH` обратимым.
- Сделать псевдоним зависимым от номера строки.
- Хранить пароль или ключ в `project.json`.
- Расширить таблицу так, что страница начинает прокручиваться по горизонтали.
- Закоммитить `demo.csv`, `__pycache__`, `.env` или `opencode.json`.
