## 1. Общее описание и назначение

**Local Table Anonymizer (LTA)** — локальное десктопное/консольное приложение, которое выполняет **обратимую анонимизацию табличных данных** (CSV, XLSX) алгоритмическими методами:

1. Персональные данные (ФИО, телефоны, email, адреса, паспортные данные и др.) в столбцах заменяются на **псевдонимы (индексы)** детерминированным алгоритмом.
2. Пользователь работает с анонимизированной таблицей любыми средствами (Excel, аналитика, отправка контрагенту и т.д.).
3. При необходимости LTA **восстанавливает персональные данные** в исходном виде по внутреннему шифрованному словарю соответствий.

### Ключевые инварианты (нарушение любого — блокирующий дефект)

- **I1. Полный офлайн.** Приложение не выполняет ни одного сетевого запроса (HTTP, DNS, WebSocket, IPC через сеть). Любая библиотека/зависимость, требующая сети, запрещена.
- **I2. Без нейросетей и ML.** Запрещены LLM, эмбеддинги, кластеризация, любой «machine learning». Только детерминированные криптографические и лингвистические алгоритмы.
- **I3. Обратимость.** Деанонимизация восстанавливает исходные значения байт-в-байт (для корректно обработанных строк).
- **I4. Псевдонимность.** Псевдонимы не содержат и не дают восстановить исходное значение без ключа и словаря.
- **I5. Приватность словаря.** Файл соответствий «индекс ↔ оригинал» хранится только зашифрованной на диске и никогда не покидает машину.
- **I6. Детерминированность.** Одинаковые входные значения + одинаковый ключ → одинаковые псевдонимы (необходимо для объединения данных и повторной деанонимизации).

## 2. Область применения

- Подготовка обезличенных выгрузок для аналитиков, подрядчиков, тестовых окружений.
- Передача обезличенных таблиц в облака/BI-системы с последующим восстановлением.
- Учебные/демо-данные: генерация синтетической таблицы (см. Приложение 2) вместо реальных ПДн.

**Вне области:** обезличивание изображений/видео/аудио, free-text (тексты писем), распознавание лиц, работа с сетевыми источниками данных, публикация словаря.

---

## 3. Термины и определения

- **ПДн** — персональные данные (столбец, отмеченный как персональный).
- **Псевдоним (индекс)** — замена ПДн вида `TEL_7F3A9C2B`.
- **Словарь соответствий (mapping)** — зашифрованная база «псевдоним ↔ оригинал + контекст строки».
- **Ключ проекта** — пароль пользователя, из которого выводится рабочий ключ (scrypt).
- **Проект LTA** — папка/файл проекта, объединяющая таблицу, конфиг обработки и словарь.
- **Режим обработки столбца** — политика замены (см. 5.2).

## 4. Функциональные требования

### F1. Импорт таблицы
- Поддержка форматов: **CSV** (UTF-8 с BOM, UTF-8, CP1251; разделители `,`, `;`, `\t`; автоопределение кодировки и разделителя) и **XLSX** (только чтение листов, без макросов).
- Автопредложение типа столбцов по эвристикам (заголовки: «телефон», «email», «ФИО», «адрес», «паспорт»; паттерны значений: 11-значные числа, email-regex и т.д.).
- Показ предпросмотра первых 20 строк и выставленных типов.

### F2. Настройка политики обработки
Для каждого столбца пользователь выбирает режим:

| Режим | Описание | Пример |
|---|---|---|
| `INDEX` | Полная замена на псевдоним (по умолчанию для ПДн) | `Иванов Иван` → `NAME_A1B2C3D4` |
| `HASH` | Псевдоним с сохранением вида (формат маскируется) | `+7 999 123-45-67` → `+7 900 000-00-00` |
| `MASK` | Частичное сокрытие (для визуальной проверки) | `ivanov@mail.ru` → `i***v@***.ru` |
| `KEEP` | Оставить как есть (не-ПДн) | — |

Дополнительно для `INDEX`: префикс индекса (`NAME`, `TEL`, `MAIL`, `ADDR`, `PSP`), опциональная нормализация перед хэшированием (убрать пробелы/скобки у телефонов, привести email к нижнему регистру).

### F3. Алгоритм псевдонимизации (без нейросетей)
Для значения `v` столбца `c` с режимом `INDEX`:

```
canonical = normalize(v, rules[c])              # нормализация
index     = PREFIX + "_" + hex(
                HMAC-SHA256(key=K_col, msg=canonical)[0:8]
            ).upper()
```

- `K_col = HKDF-SHA256(master_key, salt=project_salt || column_id)` — ключ столбца выводится из мастер-ключа, чтобы одинаковые значения в разных столбцах давали разные индексы.
- Детерминированность: повторный запуск по той же таблице/ключу даёт те же индексы (идемпотентность).
- При коллизии (редко, 32 бита) — автоматическое увеличение счётчика в словаре: `index = HMAC(... || counter)`.

### F4. Словарь соответствий
- Хранение: SQLite-файл проекта, **всегда зашифрованный** (см. 6.2), содержит: `index, column_id, canonical_value, original_value, row_key`.
- Позволяет восстанавливать данные даже если в обезличенной таблице строки переставлены/отфильтрованы: связь идёт по `index`, а не по номеру строки.
- Статистика: количество уникальных псевдонимов по каждому столбцу.

### F5. Экспорт анонимизированной таблицы
- Форматы: CSV и XLSX.
- Обезличенная таблица содержит только псевдонимы; словарь в неё **не включается**.
- Имя файла по умолчанию: `<исходное>_anon.<расширение>`.
- В метаданные XLSX допускается записывать: время обработки, имя проекта, число обработанных строк (не ПДн).

### F6. Деанонимизация (восстановление)
- На вход: обезличенная таблица (CSV/XLSX) + проект LTA + ключ.
- Восстановление по словарю по столбцам с режимом `INDEX`; для `HASH`/`MASK` — пометка «невосстановимо» (эти режимы необратимы по определению).
- Отчёт о результате: сколько значений восстановлено, сколько не найдено (значение оставлено как есть + предупреждение).
- Обратима операция над **таблицей, созданной LTA**: значения, не встречающиеся в словаре, не изменяются.

### F7. Работа с большими файлами
- Потоковая обработка CSV порциями (chunk ≥ 10 000 строк) — файлы до 500 МБ / 1 000 000 строк без загрузки в память целиком.
- Прогресс-бар и отмена операции.

### F8. Управление ключом
- Создание проекта: задать пароль (с проверкой сложности: ≥ 10 символов, отображение оценки энтропии), показать **один раз** предупреждение: «пароль невозможно восстановить; при его потере деанонимизация невозможна».
- Открытие проекта: ввод пароля, проверка через KDF-verifier (см. 6.2), 3 неудачные попытки → блокировка на 60 с (защита от перебора).
- Смена пароля: перешифровка словаря новым ключом.

### F9. Удаление данных
- «Уничтожить проект» — криптографическое стирание (перезапись словаря случайными данными + удаление файла) с двойным подтверждением.

## 5. Нефункциональные требования

- **N1. Полный офлайн:** запуск теста-проверки «нет сетевых вызовов» (см. 8.3); все зависимости — pure-local.
- **N2. Производительность:** 100 000 строк × 20 столбцов (5 из них `INDEX`) — анонимизация ≤ 60 с на MacBook Air M-сери, деанонимизация ≤ 90 с.
- **N3. Платформы:** macOS 13+ (основная), Windows 10+ (вторичная).
- **N4. Локализация:** интерфейс на русском, английский — второй язык (i18n).
- **N5. Логи:** в файл `app.log` не попадают значения ПДн и пароли (только псевдонимы и метаданные).
- **N6. Установка:** единый дистрибутив без интернет-установщика.

## 6. Архитектура

### 6.1. Выбор стека (обоснование)

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Python 3.11+: pandas, openpyxl, cryptography, Flask (localhost-only UI)** | быстрая разработка, отличная работа с таблицами, крипто-библиотека «пороховая» | нужен рантайм (решается PyInstaller) | **принять** |
| Tauri (Rust) + веб-интерфейс | малый размер, безопасно | медленнее разработка, сложнее обработка XLSX | отклонён |
| Go + gio | нативный бинарь | слабая экосистема таблиц | отклонён |
| Электрон | привычный UI | большой размер, лишняя сеть в ядре | отклонён |

**Итог:** Python 3.11+, ключевые библиотеки: `pandas`, `openpyxl`, `cryptography`, `chardet`/`charset-normalizer`, `Flask` (или `http.server`), `pytest`. Сборка — **PyInstaller** (`--onefile`), запрет сетевых плагинов.

UI: локальный веб-интерфейс Flask, слушает **только `127.0.0.1`**, случайный порт, токен в URL против DNS-rebinding. Альтернатива (если заказчик против HTTP) — PySide6; интерфейс сервисного слоя при этом не меняется.

### 6.2. Модель хранения

Каталог проекта (или единый файл `.lta`):

```
my_project.lta/                 # или архив my_project.lta
├── project.json                # метаданные: версия, salt, KDF-параметры, схема столбцов (без ПДн)
├── mapping.db                  # SQLite, зашифрованный на уровне страниц (см. ниже)
└── source_meta.json            # имя исходного файла, контрольная сумма, число строк
```

**Шифрование:**
- Пароль → `master_key` через **scrypt** (`N=2^17, r=8, p=1`, salt 16 байт из `project.json`).
- `mapping.db`: каждое поле ПДн шифруется индивидуально: `AES-256-GPU` → точнее **AES-256-GCM**, ключ = HKDF(master_key, «mapping»), nonce 12 байт уникален на запись (сохраняется рядом). Записи: `index | column_id | nonce | ciphertext(original) | mac`.
- Верификатор ключа: `verifier = SHA-256(HKDF(master_key, «verify»))` — позволяет проверить пароль, не раскрывая данные.

**Архитектура кода (слои):**

```
ui/ (Flask routes, templates)          # только вызов сервисов
services/
├── importer.py    # чтение CSV/XLSX, определение кодировки
├── profiler.py    # эвристики определения типов столбцов
├── anonymizer.py  # F3: нормализация + HMAC-индексы
├── deanon.py      # F6: восстановление по словарю
├── project.py     # жизненный цикл проекта, ключ, словарь
└── crypto.py      # scrypt/HKDF/AES-GCM, единственный модуль с криптографией
core/models.py     # dataclass: ColumnSpec, ProjectConfig, ...
```

Зависимости направлены: `ui → services → core`; `crypto` не знает о таблицах.

## 7. Пользовательский флоу

1. **Создать/открыть проект** → задать/ввести пароль.
2. **Загрузить таблицу** → предпросмотр → автопредложение типов столбцов.
3. **Настроить режимы** для столбцов (INDEX/HASH/MASK/KEEP + префикс).
4. **Анонимизировать** → прогресс → **экспорт** `*_anon.csv/xlsx`.
5. Работа с анонимной таблицей во внешних инструментах.
6. **Деанонимизировать**: загрузить обезличенную таблицу → отчёт → экспорт восстановленной.
7. При желании — **уничтожить проект**.

В интерфейсе: 4 шага-вкладки, статус текущего проекта, справка по режимам, кнопка «Экспорт отчёта обработки».

## 8. План разработки (этапы)

### Этап 0. Подготовка (2–3 дня)
- Инициализация репозитория, `pyproject.toml`, линтер (ruff), pytest, структура каталогов.
- Прототип: генерация синтетической таблицы (Приложение 2).

### Этап 1. Ядро: крипто и словарь (4–5 дней)
- `crypto.py`: scrypt, HKDF, AES-256-GCM, верификатор ключа.
- `project.py`: создание/открытие/перешифровка/уничтожение проекта.
- Юнит-тесты: корректность шифрования, невосстановимость без пароля, верификатор.

### Этап 2. Импорт и анонимизация (5–6 дней)
- Импорт CSV/XLSX, кодировки, предпросмотр.
- Профайлер типов (правила + regex).
- `anonymizer.py` (нормализация, HMAC-индексы, коллизии), `HASH`/`MASK`.
- Экспорт, потоковая обработка, прогресс.
- Тесты: детерминированность, идемпотентность, байт-в-байт round-trip.

### Этап 3. Деанонимизация (3–4 дня)
- `deanon.py`, отчёт о восстановлении, обработка дубликатов и пропусков.
- Тесты: round-trip на синтетике, устойчивость к переупорядочиванию строк.

### Этап 4. Интерфейс (5–6 дней)
- Flask-приложение, 4 шага, i18n (ru/en), прогресс/отмена (long-running задачи в отдельном потоке).
- Защита: слушать только 127.0.0.1, токен в URL, CSP без внешних ресурсов (никаких CDN!).

### Этап 5. Упаковка, проверки, документация (3–4 дня)
- PyInstaller-сборка macOS/Windows.
- Тест «офлайн» (8.3), нагрузочные тесты, ручная приёмка.
- README, руководство пользователя, changelog.

**Итого: ~3 недели** при 4–5 часах/день.

### 8.3. Тесты безопасности (обязательные)
1. **Network guard:** в тестовой среде перехват любого socket-вызова → тест падает (pytest-фикстура, запрещающая `socket.socket.connect`).
2. **Round-trip:** `deanon(anon(T)) == T` для всех строк синтетики.
3. **Детерминированность:** два запуска дают идентичный `anon(T)`.
4. **Невосстановимость:** по `anon(T)` без ключа/словаря исходные значения не восстанавливаются brute-force быстрее перебора (проверка длины/энтропии индекса).
5. **Утечки в логах:** grep-тест на отсутствие ПДн в `app.log` и метаданных экспорта.

## 9. Критерии приёмки

1. Анонимизация синтетической таблицы (10 000 строк, 15 столбцов, 6 ПДн-столбцов) без ошибок; все ПДн-столбцы содержат только индексы вида `PREFIX_XXXXXXXX`.
2. Деанонимизация возвращает исходные значения байт-в-байт для 100% строк.
3. Приложение работает при отключённом/отсутствующем сетевом интерфейсе.
4. В коде нет обращений к ML-библиотекам (проверка зависимостей).
5. Файл `mapping.db` в незашифрованном виде недоступен: без пароля чтение невозможно.
6. Потеря пароля ⇒ деанонимизация невозможна (подтверждается тестом).
7. Обработка файла 100 000 строк укладывается в N2 по времени.
8. Установка и запуск на чистой машине без интернета.

## 10. Риски и способы снижения

| Риск | Влияние | Снижение |
|---|---|---|
| Потеря пароля заказчиком | потеря возможности деанонимизации | предупреждение при создании, рекомендация хранить пароль в менеджере паролей |
| Коллизия HMAC-индексов | редкая путаница значений | счётчик + уникальный индекс в словаре |
| Кодировки CSV (CP1251 и др.) | «кракозябры» → неверная нормализация | chardet + ручной выбор + предпросмотр |
| Работа с файлами > памяти | падение | потоковая обработка (F7) |
| Утечка ПДн через имя файла/логи/метаданные | компрометация | требования N5, тест 5 |
| Случайная отправка словаря вместе с таблицей | компрометация | словарь — отдельный зашифрованный файл, экспорт только анонимной таблицы |
| Высасывание ПДн из статистики (k-анонимность) | реидентификация | рекомендация: не экспортировать столбцы с 1–2 уникальными значениями; предупреждение в отчёте |

## 11. Приложения

### Приложение 1. Словарь префиксов индексов (по умолчанию)

`NAME_` ФИО · `TEL_` телефон · `MAIL_` email · `ADDR_` адрес · `PSP_` паспорт · `DOB_` дата рождения · `ID_` прочие идентификаторы (пользователь может добавить свои).

### Приложение 2. Синтетическая тестовая таблица (генератор)

Скрипт `make_demo.py` создаёт `demo.csv` (10 000 строк) со столбцами:
`id, ФИО, телефон, email, дата_рождения, город, адрес, паспорт, заказ, сумма, дата_заказа` — значения генерируются из встроенных словарей (русские фамилии/имена/отчества, +7 9XX XXX-XX-XX, домены `example.com`) с контролируемым числом дубликатов и пропусков (~2% null). Реальные ПДн в разработке не используются.

### Приложение 3. Пример строки словаря (схема)

```
index=NAME_A1B2C3D4 | column_id=col2 | nonce=<12B> |
ciphertext=<AES-256-GCM(ФИО «Иванов Иван Иванович»)> | mac=<16B>
```
