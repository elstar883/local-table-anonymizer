- `scripts/make_demo.py` — генератор синтетической таблицы;
- `scripts/e2e.sh` — запуск сервера и E2E;

- `references/acceptance-report.md` — отчёт о приёмке;

- `.opencode/commands/` — команды `lta-plan`, `lta-build`, `lta-qa`;

## 1. Язык

- Общайся с пользователем только на русском языке.
- Интерфейс, сообщения, ошибки и подсказки приложения — по-русски.
- Технические имена файлов, функций и коммитов — на английском.

## 2. Источники требований

- Перед планированием прочитай `references/requirements.md`,
  `references/acceptance-report.md`, `docs/ARCHITECTURE.md` и `SECURITY.md`.
- `references/requirements.md` — исходное ТЗ, не переписывай его под реализацию.
- Если реализация расходится с ТЗ, зафиксируй это явно в README, в разделе
  «Ограничения», и в `references/acceptance-report.md`.
- Все имена, телефоны, адреса, паспорта и суммы — синтетические.
- Демонстрационная таблица генерируется `scripts/make_demo.py` и не коммитится.

## 3. Блокирующие инварианты

Нарушение любого пункта — блокирующий дефект:

- **I1. Полный офлайн.** Ни одного сетевого запроса: HTTP, DNS, WebSocket, IPC
  через сеть. Только `127.0.0.1`. Никаких внешних API, CDN, шрифтов, картинок и
  аналитики.
- **I2. Без ML.** Никаких LLM, эмбеддингов, кластеризации, обучения. Только
  детерминированные правила, regex, HMAC, scrypt, HKDF, AES-GCM.
- **I3. Обратимость.** `INDEX` восстанавливается байт-в-байт по словарю.
  `HASH` и `MASK` необратимы по определению.
- **I4. Псевдонимность.** Псевдоним не содержит исходное значение и не даёт
  восстановить его без ключа.
- **I5. Приватность словаря.** Оригиналы хранятся только зашифрованными
  (AES-256-GCM) и не покидают машину.
- **I6. Детерминированность.** Одинаковое значение + тот же проект + тот же
  столбец → тот же псевдоним.

- `references/requirements.md` доступен только для чтения.
- Код приложения — в `lta/`, `main.py`, `tests/`, `scripts/`.
- Документация и портфолио-оформление — в `README.md`, `docs/`,

- Не удаляй исходное ТЗ и не переписывай согласованные требования.
- Не добавляй реальные персональные данные, дампы, архивы и PDF.
- Не коммить `.env`, `opencode.json`, `opencodemcp.json`, `demo.csv`,

- До подтверждения плана не меняй файлы приложения.

## 5. Технологии

- Python 3.11+.
- Flask 3.1 для локального HTTP-интерфейса.
- `cryptography` для scrypt, HKDF, AES-256-GCM.
- `openpyxl` для XLSX.
- SQLite из стандартной библиотеки для словаря.
- Никаких pandas, ML-фреймворков, внешних API и сетевых клиентов в runtime.
- `requests` и `pytest` — только для разработки и тестов.

## 6. Структура и ответственность

- `lta/app.py` — только HTTP-маршруты, встроенный UI и фоновые задания; не
  реализуй здесь криптографию.
- `lta/core.py` — анонимизация и деанонимизация; не знает о Flask.
- `lta/transform.py` — типы, нормализация, `HASH`, `MASK`; не знает о проекте.
- `lta/project.py` — жизненный цикл проекта и словарь; не знает о форматах
  таблиц.
- `lta/crypto.py` — единственный модуль с примитивами; не знает о таблицах.
- `lta/tableio.py` — только чтение/запись CSV и XLSX.
- Дополнительные файлы создавай только при реальной необходимости.

## 7. Модель данных

- Проект — каталог `.lta` с `project.json` и `mapping.db`.
- `project.json` содержит версию, соль, параметры KDF, верификатор и схему
  столбцов. Исходных значений там быть не должно, кроме `sample` (осознанное
  ограничение MVP).
- `mapping.db` содержит `column_id`, `index_val`, `canon_hmac`, `orig_enc`.
- `orig_enc` — `nonce || AES-256-GCM ciphertext + tag`, всегда зашифрован.
- Поиск при деанонимизации идёт по `(column_id, index_val)`, а не по номеру
  строки.
- `column_id` — имя столбца; одинаковые значения в разных столбцах получают
  разные псевдонимы.
- Не меняй формат `mapping.db` без миграции и обновления документации.

## 8. Безопасность

- Сервер слушает только `127.0.0.1`, никогда `0.0.0.0`.
- Все `/api/` и `/download/` маршруты требуют токен.
- Не логируй ПДн и пароли.
- Не добавляй внешние ресурсы в HTML/CSS/JS.
- Не отключай проверку токена и не делай API публичным.
- Не храни пароль в файлах, коде, тестах или документации.
- Помни: `uploads/` хранит исходные и восстановленные файлы в открытом виде.
- Уничтожение проекта — best effort, не гарантирует forensic-стирание.

## 9. Проверки

Перед завершением этапа:

```bash
python3 scripts/validate.py
python3 tests/test_lta.py
bash scripts/e2e.sh
```

- `validate.py` должен вывести `OK`.
- Юнит-тесты — `6/6`.
- E2E — `0 расхождений`.
- Для изменений UI проверь 1440, 768, 390 и 360 px.
- Для изменений криптографии или словаря добавь тест на round-trip,
  детерминированность и неверный пароль.
- CI должен быть зелёным на `main` и `develop`.
